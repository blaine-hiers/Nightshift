How Nightshift works

Nightshift is not a software project. It's the working environment that turns Linear issues into pull requests against other repos. The one thing to understand first: Linear is the system of record — work starts from a Linear issue and ends with that issue updated, and nothing here tracks the target repos' code, only the skills and docs that encode the workflow.

Inputs

  • Linear issues in Todo (or named in conversation)
  • Target repo clones under workspace/
  • Doppler dev secrets — only when a ticket needs live calls

Outputs

  • PRs against target repos, referencing ENG-NN
  • Linear comments: root cause, repro, PR link
  • Run reports in docs/runs/
  • Skill improvements — the commits this repo is made of

Depends on

  • Linear MCP (mcp__claude_ai_Linear__*)
  • gh CLI with push access (or fork)
  • Doppler CLI, directory-scoped
  • codex CLI, logged in — only for Tier/Codex tickets

Never tracked here

  • workspace/ — gitignored
  • Any target repo code
  • Any .env value

Codex path — Tier/Codex tickets

Same ticket loop, different implementer. Codex writes the code and commits; Claude does everything else — every Linear write, the worktree, the push, the PR, the review. Codex runs sandboxed with network off, so its only way out of the worktree is Claude's push, and that push is gated by a secret scan. Opt-in only: a ticket gets Tier/Codex because a human asked for Codex, never as a cost/difficulty derivation.

What Codex may do

  • Read anything in its worktree (workspace-write limits writes, not reads — so no .env may be there)
  • Edit, run the repo's tests, commit to the current branch

What Codex may never do

  • Reach the network (network_access=false pinned on the command line)
  • Push, open a PR, or touch Linear
  • Be resumed with --last — parallel runs would cross-resume

Budget

  • 30 min wall-clock per ticket — provisional, first real run is attended and measured
  • 2 attempts (fresh session each); the fix round is separate and comes out of the review
  • Max 2 Codex tickets concurrent, each backgrounded

Attribution

  • PR body line + Linear close-out comment are the record that Codex authored it
  • If Claude ends up writing code to rescue the ticket, say so in both places and reconsider the tier label

04 Permissions & access model

Who may write where. Nightshift has no auth system of its own — the access model is a set of rules in CLAUDE.md, and the matrix below is what they add up to.

Roles

human

Files and sharpens issues, approves plans, reviews and merges PRs, unsticks Needs Input.

coordinator

The main session. Only principal that writes to Linear or creates/removes worktrees.

subagent

Implementer or reviewer. Lives inside one worktree; reports back as text.

codex

OpenAI Codex CLI as implementer on Tier/Codex tickets. Sandboxed to one worktree, network off; commits but never pushes. Strictly less than a subagent.

sweep.sh

Script. Classifies worktrees; deletes only with --remove and only REMOVABLE ones.

Where it's NOT enforced None of this is enforced by tooling — it's convention in CLAUDE.md read by the model each session. The only mechanical guards are git worktree remove refusing a dirty tree, .gitignore excluding workspace/, Doppler's directory scope, and — for Codex — the CLI's own sandbox (workspace-write, network_access=false) plus timeout. git-guardrails-claude-code is installed as a skill but its hook is not active (its default list blocks git push, which this workflow needs).

Where state lives

  • Linear — issue status, labels, comments, project descriptions (source of truth)
  • Target repo on GitHub — branches, PRs, CI
  • Disk — base clones + worktrees (ephemeral, gitignored)
  • docs/runs/ — the only state Nightshift commits about a run
  • Scratchpad — Codex .out/.log per ticket; the session UUID inside is what the fix round resumes and the Linear comment records

Sensitive data

  • Doppler dev secrets land in a worktree's .env only on opt-in; removed with the worktree
  • .env.example carries names only, never values
  • Security label marks issues touching credentials, redaction, exposure — seeds variant-analysis sweeps

Start a ticket by hand

git clone <url> workspace/<repo>     # once
cd workspace/<repo>
git fetch origin
git worktree add .worktrees/ENG-42 \
  -b <gitBranchName> origin/main

Drain the queue

/queue-drain
# or: "drain the queue"
bash .claude/skills/queue-drain/scripts/sweep.sh workspace/<repo>
bash … sweep.sh workspace/<repo> --remove

Dispatch to Codex (Tier/Codex)

codex --version && codex login status   # once per run
timeout 600 codex exec -m gpt-5.6-terra \
  --config model_reasoning_effort="high" \
  --config sandbox_workspace_write.network_access=false \
  --sandbox workspace-write --full-auto --skip-git-repo-check \
  -C .worktrees/ENG-42 -o $SCRATCH/codex-ENG-42.out \
  "<description verbatim + contract>" </dev/null 2>$SCRATCH/codex-ENG-42.log
grep -m1 '^session id:' $SCRATCH/codex-ENG-42.log   # keep the UUID
# fix round: … resume <uuid> "findings"  (never --last)

Tear down

git -C workspace/<repo> worktree remove .worktrees/ENG-42
git -C workspace/<repo> worktree prune
git worktree list    # find leftovers

Known failure modes

  • Subagent lands in an empty tree → someone used isolation: "worktree" (worktrees Nightshift, not the target)
  • Two agents fighting over build state → they share a checkout; one worktree per ticket
  • Flags silently dropped on the server → npm run strips them; call node scripts/x.mjs --flag directly
  • Same blocker rediscovered every drain → a stalled issue was returned to Todo instead of an off-ramp
  • 400 MB of dead clones → teardown skipped at Done; run the sweep
  • Codex hangs with zero output and zero CPU → stdin left open; append </dev/null
  • Codex exit 124 or empty -o file → timeout killed it; that's the timeout lane, whatever the log says
  • Fix round landed on the wrong ticket → resume --last with parallel runs; resume by UUID
  • Wrong UUID captured → grep hit the workdir: path; anchor on the session id: line
  • Codex silently on a different model after resume → flags not re-passed; repeat model, effort, sandbox, worktree
Do not Work in the base clone. git add workspace/ from the root. rm -rf a worktree. Copy a .env between worktrees. Touch prd. Put DOPPLER_TOKEN in a subagent's environment. Pass a label name like Tier/Sonnet straight into model:. Park an unworkable issue in Todo. Dispatch with permission-skip flags. Fake a green gate. env-sync into a Codex worktree. Let Codex push. Resume Codex with --last. Push a Codex diff without the secret scan.

09 Glossary & changelog

Terms

Base clone
workspace/<repo>; stays on main, exists to be branched from and fetched into.
Worktree
.worktrees/ENG-NN under the base clone; one per issue; the only place a fix is edited.
Coordinator
The main Claude session; owns Linear writes, worktrees, and the report.
Off-ramp
Needs Input (ask unworkable) or Blocked (external dependency) — honest parking for a stalled issue.
BLOCKED tree
A worktree that fails the sweep's three tests; reported, never deleted. Independent of Linear's Blocked status.
Tier
The model an issue needs, recorded once as Tier/…; label is capitalized, model: string is lowercase.
Drain
One /queue-drain run: sweep → fetch → triage → plan gate → fan-out → verify → close → retro.
Codex / Tier/Codex
The OpenAI Codex CLI as implementer, opted into per ticket by a human. Not a Claude tier: maps to no model: string; routes to codex-dispatch.
codex-dispatch
First-party skill: the Linear lifecycle around a sandboxed codex exec — Codex commits, Claude verifies, pushes, opens the PR, reviews, and runs one fix round.
Session UUID
Codex's session id, read from the session id: log line. The fix round resumes by it (never --last) and the Linear close-out records it.
