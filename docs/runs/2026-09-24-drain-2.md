## What the reviews caught

- **#21:** `openInCalculator` merged hardware instead of replacing it, so a stale offload setting or Apple override survived a Planner "Use".
- **#26:** Undo lost the speculative config. A Planner clear brought back the Calculator's undo banner. Planner Undo special-cased one field, which would have silently dropped #24/#25 state once they landed.
- **#24:** crafted `pt_` URL values weren't clamped ("21800 PB headroom"). With "any" hardware, rows didn't name their GPU.
- **#25:** stale speculative config on "Use", fixed in the shared reducer so #24 benefits too. Priced GPUs always ranked above unpriced ones, which buried an owned RTX 4090 under 8× H100. The coordinator decided to default to "smallest first" and add a "cheapest $/hr" option.
- **Integration:** rows at an unclamped context disagreed with "Use" (the invariant has to hold across a model change); `ph*` URL values weren't clamped; "Size hardware" did nothing once step 2 had a pick; the handoff wasn't persisted. The re-review then checked about 79,000 generated rows for row == "Use".
- **Found by the catalog change:** reordering `MODEL_PRESETS` silently changed two defaults that read `MODEL_PRESETS[0]`: the speculative draft model and step 2's fallback. They now name their preset by id.

## Skills

- Updated `queue-drain/references/integration-batch.md` with this run's lessons:
  - Put foundation tickets first, and have them publish explicit contracts: file slots, a state sub-slice per ticket, a handoff callback. Then parallel tickets touch disjoint files.
  - Give parallel tickets distinct URL-key prefixes.
  - Hidden-but-mounted tab panels make duplicate accessible labels break `getByLabelText`. Tell implementers to use distinct labels.
  - Any action that loads a derived "row" into the main state must satisfy **row == calculate(state after load)**. Clamp in one shared helper, and test through the real reducer.
  - A jsdom suite that renders the full app needs a raised `testTimeout`.
