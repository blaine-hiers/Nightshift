## What the reviews caught

The substantive result of this drain is not the styling. **Every repo's README
overclaimed somewhere**, and the two-reviewer gate caught it instead of
repainting over it:

- **Bindery** documented a *"Contradictions — two documents that state a different value for the same thing"* gap-report finding. No such detector has ever existed; a repo-wide grep finds only an unrelated score-arithmetic comment and a test helper asserting the readiness score's own arithmetic. Two findings that *are* real and score-weighted (`unreadable`, `concentration`) were undocumented. Both reviewers independently confirmed before the removal shipped.
- **Dawnpatrol** claimed 68 tests; the suite runs 92.
- **Legwork's** *new* diagram invented a UI detail — "found next to missed, side by side" — when `paintDemo()` appends the cards sequentially with no flex/grid rule. Caught at stage 5, fixed, re-verified at stage 6.
- **Gauntlet's** diagram labelled a node `ClaudeCliProvider.execute`; the real method is `run` and no `execute` exists. **The two reviewers disagreed** — stage 5 accepted it as "an interface description", stage 6 called it an invented method. Stage 6 was right. This is the clearest evidence so far that the two-reviewer design earns its cost.
- **Onramp's** `package-lock.json` declares `ISC` while `package.json` and `LICENSE` say MIT. Out of scope for a README PR, so filed as [Onramp#4](https://github.com/blaine-hiers/Onramp/issues/4) rather than folded in.

One follow-up cannot be fixed by any PR here: **Bindery's GitHub repo
description also says "contradictory"**. Repo descriptions live outside git.

## Pipeline friction

1. **Stale base clones poisoned two ticket bodies.** The pre-drain survey
   measured READMEs from `workspace/<repo>` working trees rather than
   `origin/main`. Redline was described as 359 lines with 4 screenshots
   (really 161 and 8); Gauntlet as 143 lines (really 311). The implementers
   worked from the real files and flagged the mismatch, so nothing shipped
   wrong — but each error spends a subagent's attention reconciling the ticket
   against reality. Fixed by a new warning in `docs/workspace.md`.
2. **Coordinator status-label lapse.** Redline#4 and Nightshift#4 sat in
   `status/todo` while their implementers ran, because labels were moved for
   the wave-1 batch but not for the two staggered dispatches. Exactly the
   "don't batch status updates" failure CLAUDE.md warns about, committed by
   the coordinator. Corrected mid-run. No skill change — the rule already
   exists and was simply not followed.
3. **WIP cap briefly exceeded.** Six tickets were in flight at once when
   Redline was dispatched while Legwork was still in review. Within the spirit
   of the cap (only one implementer was running) but over its letter. Worth
   defining whether "in flight" counts tickets or running implementers.
