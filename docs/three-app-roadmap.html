01 The three apps

They are not a suite. They are three points on one engagement arc for a solo advisory practice — know something worth saying, prove it in the room, then deliver something the client keeps.

Dawnpatrol — intel

  • 27 feeds swept before the day starts
  • One story, not six copies of it
  • Ranked for owner-led SMBs, arithmetic shown

Legwork — the sale

  • A workflow the owner recognises in ten seconds
  • Real extraction on their own pasted email
  • Never a single figure, never an invented rate

Bindery — delivery

  • Sub-second search over their own folder
  • Duplicates, stale, orphans, what is missing
  • Read-only, verified by test

Shared by all three

  • Standard library only, no dependencies
  • Local-first, no account, no telemetry
  • One vendored _shared/ kit

02 Theme A — honour “nothing is hidden”

All three apps state this principle in their README. All three break it in exactly one place. This is the cheapest, highest-credibility work available.

AppWhere it breaksState
Dawnpatrolbuild() returned merged[:40]; the UI could not reach the restfixed · PR 7
BinderyFixed category order, then return out[:5] — analyze.py:724phase 1
LegworkChase demo drops comma-less lines, despite its own on-screen hintfiled · #5
Why Bindery’s is the worst The headline block is the part an advisor reads aloud in the room. A catastrophic concentration finding can be pushed off that list by nothing more than its position in an if/elif chain. Replace the fixed order and the cap with a severity sort that shows its own arithmetic — hours of work, no I/O, no schema change. It is also a prerequisite for every later finding type: add those first and each one needs its own bespoke priority rule.

Legwork #3 blocks every Legwork item Only the first field edit per sheet is saved; every later edit is silently discarded, because save() swaps the object graph out from under handlers bound at the last paint. Both the stored document and the live numbers freeze. Every Legwork feature in this roadmap assumes a sheet that saves.

Phase 0 in full: merge the six open PRs — all report MERGEABLE, and #5 and #7 were verified to auto-merge cleanly despite touching the same two files; clear the correctness backlog (Dawnpatrol #9–#12, Legwork #4–#6, Bindery #4); and decide Bindery #3.

On 2

The source list was verified once, in August. Two feeds have degraded since — VentureBeat a persistent 429, ZDNet a 404 — and nothing surfaced that drift. “A broken source is on the screen, not in a log” holds one morning at a time, and is defeated in aggregate.

On 3

The backend already accepts windowDays 1–14. The UI posts an empty body and can never ask for it. Pure wiring, for the “I was on-site for four days” case.

On 4

The sheet already collects who per step but applies one blended rate to all of them. An owner who runs payroll will notice a $22/hr office hour priced identically to a $95/hr tech hour.

On 6

“All 340 unreadable files live in one pre-2015 archive folder” is a remediation plan. “Here are 12 reasons files fail” is not.

06 Phase 2 — close Theme B

Make each artifact carry the judgment its session produced.

#AppItemSize
7LegworkPin a live-demo result into the exported one-pagerM
8DawnpatrolKept-list call-prep export, optional flat client tagM
9BinderyRe-engagement trend — snapshot each scan, show deltasM
Item 7 carries a privacy risk that must be designed in, not bolted on Pasted customer text contains real names and addresses. Pinning a demo result into an exported file needs an explicit, visible “include this in the export?” confirmation. Silently baking a customer’s details into a leave-behind would be a serious misstep.

Item 9 needs a retention cap, so a five-year engagement does not grow an unbounded database — and must show its arithmetic rather than becoming “the score went up” theatre.

07 Phase 3 — ambitious

10 · Bindery — contradiction detection decision pending

General semantic contradiction detection is not achievable at acceptable false-positive rates without an NLP model, which the constraints forbid. The buildable version is a closed set of hand-authored fact extractors — labour rate, payment terms, warranty length, insurance limit, price-list effective date — each a pattern requiring a fixed anchor phrase adjacent to the value. Two values for the same field key, in different documents, differing beyond a tolerance, become a “same fact, different files, different values” finding shown with both snippets. The advisor confirms; the tool never declares.

False-positive control is architectural, not statistical It only ever compares numbers adjacent to the same anchor phrase from a short curated list — never any two numbers near any two phrases, which is what would cry wolf on every page count and invoice total in the folder. The honest cost is recall, and the report must say so rather than let “no contradictions found” read as “verified consistent.” If it cannot reach near-zero false positives, the right outcome is to drop the README claim and ship a smaller “known business facts, side by side” table with no contradiction language at all. That is a good result, not a failure.

11 · Dawnpatrol — cross-day story threading

Match today’s merged stories against yesterday’s stored report and annotate “continuing — first seen {date}” instead of presenting a third-morning story as brand new. Must land after #9, which fixes the merge path it depends on, and needs its own decay term: a story resurfacing for the third day is not automatically more important, and without that the ranking starts rewarding staleness.

12 · Dawnpatrol — band-diversity-aware corroboration

A lab post plus a practitioner writeup plus a wire story is stronger evidence than three outlets syndicating one press release. Story.also currently stores only source and url — no band — so the corroboration bonus is blind to exactly the distinction the band system exists to draw.

13 · Legwork — a real “who goes where” demo

The one handling answer with no runnable demo. A deterministic greedy first-draft assignment, with the reason written beside each one, framed as a draft the owner edits. The picker is already honest here — that entry’s blurb reads “Not built yet. Named here so the sheet doesn’t imply it exists” — so this is an opportunity, not a repair. Needs explicit “assumed, not told” flagging, or it starts to look like judgement was quietly automated.

14 · Legwork — second-visit delta report

Re-enter measured numbers after a build; compare the original range against observed reality, still as ranges. A pure diff of two analysis snapshots. The only feature here that operates after the sale, which is why it matters for a repeat-engagement practice.

15 · Bindery — cross-folder comparison

Point at the official shared drive and someone’s personal export; report what exists in both with different content. The index already partitions by client and the near-duplicate algorithm is already agnostic to it. For an SMB with no IT department this is often the finding that explains why the documentation is unreliable. Keep it narrowly framed, or it scope-creeps into a general folder-diff product.

16 · Bindery — headless batch mode

Scan and export from the command line without the server. Twelve active clients currently means opening the GUI twelve times. Must share the same functions as the GUI path, not reimplement them.

08 What we will not build

Recorded so the same tempting ideas do not get re-proposed each quarter. Each of these is popular, plausible, and would damage the thesis of the app it lands in.

Not thisBecause
A “top 5 only” mode
Dawnpatrol		The most requestable feature, and the one that guts the founding refusal. You cannot audit an absence.
Self-tuning ranking weights
Dawnpatrol		If the keyword table can change without a human editing it, a Tuesday score is no longer traceable. A suggestion the advisor commits by hand is fine; an automatic reweight is not.
Industry benchmarks
Legwork		The one-pager already prints “These are your numbers, not an industry average.” There is no dataset behind a solo practice, and a stranger’s numbers on this owner’s page is what the trust model exists to prevent.
Auto-suggested handling ticks
Legwork		The code already refuses to guess these on import — “guessing it would put ticks on a client’s sheet that the client never made.” They are worth something only because the owner said them.
A suggested hourly rate
Legwork		Once one dollar figure on the page is soft, none of the others can be trusted.
LLM summarisation
Bindery		Breaks stdlib-only and no-network, and undoes the actual differentiator: inspectable, boring determinism the advisor can point at.
Any write path
Bindery		Turns “this app cannot write” into “this app can write, but only when a flag is off” — a categorically weaker promise to make a client.
A bundled OCR engine
Bindery		No standard-library OCR exists. Page-count triage captures most of the value without crossing the line.
Hosted or synced anything
all three		Local-first is the trust model, not a deployment detail.
